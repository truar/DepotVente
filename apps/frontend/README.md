# Frontend

The offline-first React app the volunteers use on the client PCs. See the root
`Readme.md` for the project and `.claude/CLAUDE.md` for the sync model.

## How it works

- **Local first.** Every screen reads and writes the browser's IndexedDB
  through Dexie (`src/db.ts`). The server is only reached by the sync worker.
- **Sync worker** (`src/workers/sync.worker.ts`, `src/services/sync-service.ts`):
  pushes the outbox to `/api/push` in write order and polls `/api/sync/delta`
  every 20 seconds. Every request carries the computer's identity
  (`src/services/client-identity.ts`) and the dataset epoch; a server reset
  raises the blocking dialog in `src/components/custom/DatasetResetDialog.tsx`.
- **Routing** with TanStack Router (`src/routes/`, tree generated by the Vite
  plugin into `src/routeTree.gen.ts`). Admin routes are guarded in
  `src/lib/route-guards.ts`.
- **Printing**: DYMO labels (`src/hooks/useDymo.ts`, `public/*.label`) and
  PDF reports with `@react-pdf/renderer` (`src/pdf/`).
- **Offline shell**: a service worker precaches the build (see the notes in
  `vite.config.ts` and `src/main.tsx`; a new build only takes over when the
  browser is reopened).

## Commands

```bash
pnpm dev         # Vite on http://localhost:15173, /api proxied to the backend
pnpm build       # production build + type check
pnpm test        # vitest: application tests in src/test on an in-memory IndexedDB
pnpm check       # prettier --write + eslint --fix
```

## Tests

`src/test/harness.ts` drives the app through its real hooks against the real
Dexie schema (fake-indexeddb, jsdom). Scenarios live in `src/test/scenarios/`;
start from `deposit.test.ts`.
